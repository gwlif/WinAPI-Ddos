# IPC Security Lab (WinAPI / C)

Учебное многопроцессное приложение для Windows на C. Родительский и дочерний процессы обмениваются набором двумерных точек через именованный канал; дочерний процесс сортирует данные, выполняет локальную полиномиальную интерполяцию и отображает график средствами Win32/GDI.

Проект демонстрирует практическую работу с WinAPI, межпроцессным взаимодействием (IPC), синхронизацией потоков, валидацией входных данных, обработкой ошибок и тестированием. Это учебная лаборатория, а не production-система аутентификации и не универсальный защищённый IPC-протокол.

## Возможности

- Родительский и дочерний процессы, запуск дочернего процесса через `CreateProcessA`.
- Именованный канал с уникальным именем для каждой попытки соединения, явной DACL, запретом удалённых клиентов и проверкой PID подключившегося процесса.
- Анонимный канал и события Windows для уведомлений; управляемое завершение фоновых потоков.
- Проверка размера IPC-сообщений, числа точек, конечности и диапазона координат до использования данных.
- Проверка полученного результата сортировки.
- Обновление данных из `data.txt` через временный буфер с проверкой перед заменой текущего набора.
- Карманная сортировка с обработкой отказов выделения памяти.
- Локальная полиномиальная интерполяция с нормализацией координат и обработкой неустойчивых случаев.
- Графическое окно Win32/GDI и журналирование отдельных событий в `security.log`.
- C-тесты для валидации IPC, ACL, сортировки, файловых уведомлений и интерполяции; Python-регрессионные тесты; сборка и тесты на Windows runner через GitHub Actions.

## Требования

Для запуска приложения требуются Windows, Windows SDK и компилятор MSVC. Переносимые C-тесты можно запускать в macOS/Linux при наличии совместимого C-компилятора. Python-регрессионные тесты требуют Python 3.

## Сборка на Windows

Сборка выполняется из **Developer Command Prompt for Visual Studio**:

```bat
cl /nologo /W4 /utf-8 /std:c11 /D_CRT_SECURE_NO_WARNINGS main.c user32.lib gdi32.lib advapi32.lib bcrypt.lib
```

Приложение `app.exe` следует запускать из каталога, содержащего `data.txt`, поскольку путь к файлу относительный.

Для учебного сценария конкурирующих подключений предусмотрен режим `PROC3`. В качестве аргумента используется точное имя канала, которое приложение выводит после создания IPC-объекта:

```powershell
.\app.exe PROC3 "\\.\pipe\Task5NamedPipe-<nonce>"
```

Вместо `<nonce>` указывается фактический суффикс из сообщения приложения. Это локальный тестовый сценарий; запуск против чужих систем и публикация приложения в сети не предусмотрены.

## Формат `data.txt`

Файл содержит пары чисел `x y`, разделённые пробелами и/или переводами строк. Каждая координата должна быть конечным числом в диапазоне `[-1000; 1000]`. Для работы требуется от 2 до 100 допустимых точек. Пример входных данных включён в репозиторий.

## Запуск проверок

### macOS / Linux: переносимые проверки

```bash
sh run_local_checks.sh
```

Скрипт компилирует и запускает переносимые C-тесты валидации IPC, сортировки и интерполяции, затем выполняет Python-регрессионные тесты. Проверки, напрямую зависящие от WinAPI, выполняются на Windows.

### Windows: полный набор

Команды выполняются из Developer Command Prompt for Visual Studio:

```bat
cl /nologo /W4 /WX /utf-8 /std:c11 tests\test_ipc_validation.c /Fe:ipc_validation_tests.exe
ipc_validation_tests.exe

cl /nologo /W4 /WX /utf-8 /std:c11 tests\test_pocket_sort.c /Fe:pocket_sort_tests.exe
pocket_sort_tests.exe

cl /nologo /W4 /WX /utf-8 /std:c11 tests\test_interpolation.c /Fe:interpolation_tests.exe
interpolation_tests.exe

cl /nologo /W4 /WX /utf-8 /std:c11 tests\test_directory_notify_windows.c /Fe:directory_notify_tests.exe
directory_notify_tests.exe

cl /nologo /W4 /WX /utf-8 /std:c11 tests\test_ipc_security_windows.c advapi32.lib /Fe:ipc_security_tests.exe
ipc_security_tests.exe

python -m unittest discover -s tests -p "test_*.py" -v
```

Workflow `.github/workflows/windows-build.yml` собирает приложение и тесты на Windows runner и сохраняет `app.exe` как артефакт. Успешная сборка и автоматические тесты не заменяют ручную проверку GUI, завершения потоков и поведения IPC при конкурирующих подключениях. 

## Реализованные проверки безопасности

- Ошибка чтения логина или неверный логин приводит к отказу до загрузки данных.
- До расчёта размера массива IPC проверяется допустимое количество точек.
- Координаты проверяются на конечность и допустимый диапазон; результат проверяется на сортировку.
- Именованный канал использует уникальное имя, DACL, запрет удалённых клиентов и проверку PID клиента.
- Строковые IPC-сообщения принимаются только при допустимом размере и наличии завершающего NUL в пределах сообщения.
- Данные файла сначала загружаются во временный буфер и проверяются до обновления рабочего набора.
- Сортировка обрабатывает ошибки выделения памяти; графический код проверяет создание ресурсов и восстанавливает выбранные GDI-объекты перед удалением.

## Ограничения

- **Аутентификация демонстрационная.** Пароль короткий и детерминированно зависит от введённых слов; DJB2 не предназначен для безопасного хранения паролей. Пароль также выводится при регистрации. Этот механизм непригоден для реальных учётных записей.
- `PIPE_PROTOCOL_MAGIC` — маркер протокола, а не цифровая подпись, MAC или шифрование. ACL, уникальные имена и проверка PID повышают уровень защиты IPC, но не доказывают устойчивость ко всем локальным атакам или отказу в обслуживании.
- Бинарный формат сообщений рассчитан на процессы одной сборки и совместимую архитектуру.
- Локальная полиномиальная интерполяция не является классическим кубическим сплайном с гарантированной непрерывностью производных. Нормализация улучшает численную обусловленность, но не гарантирует устойчивость при любых входных данных.
